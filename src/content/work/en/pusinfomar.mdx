## Context

An internal application supporting day-to-day work inside an institution. Its users are not people who live in design tools, so the interface has to be understandable without long training.

## My role

Interface designer: gathering requirements, mapping workflows, building wireframes, then executing high-fidelity mockups and a prototype in Figma until the design was approved.

## Constraints

- **Some project details are restricted**, so this page shows the design process — not real data or screenshots.
- Requirements arrived verbally and in stages, not as a specification document.
- Design decisions had to be justifiable to non-designer stakeholders.

## Process

1. **Mapping the main user tasks**, then writing a user flow for each.
2. **Low-fidelity wireframes** to test the information order before discussing visuals.
3. **High-fidelity mockups** built from reusable components.
4. **An interactive prototype** to test flows, then iterating on feedback.
5. **Preparing assets and a component guide** for the development team.
