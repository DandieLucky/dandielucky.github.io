## Context

An internal application for field users, inside an environment with strict procedures. The interface has to be clear at a glance, because people use it while on the move.

## My role

UI/UX designer: gathering requirements from users, shaping the flows, producing wireframes, then building the prototype and the component guide.

## Constraints

- Some details are restricted by institutional policy — the screens shown here stay within what is allowed.
- Not every user is comfortable with complex applications.
- Every element needs a reason; no decoration that eats space.

## Process

1. **Gathering requirements** through interviews and observing the existing workflow.
2. **Mapping user flows** from the most frequent tasks down to edge cases.
3. **Producing low-fidelity wireframes** to test the order before any visual work.
4. **Building a clickable prototype** and testing it with users.
5. **Writing the design system**: components, spacing, and status rules so future screens stay consistent.

## Outcome

- A workflow that used to live in written procedures now has a shape on screen.
- The design system lets new screens be added without reworking what has already been approved.
